طراحی سامانه مدیریت آموزشی «گلستان»

سامانه‌ای برای ثبت دانشجویان، استادان و کلاس‌ها، ثبت‌نام در کلاس‌ها، تخصیص استاد، ورود نمرات و گزارش‌گیری پیاده‌سازی کنید. برنامه باید از سه فاز مسئله اصلی پشتیبانی کند. کلاس‌های شی‌گرای پیشنهادی و Propertyها الزامات آموزشی این نسخه هستند؛ پیام‌های خطا و قواعد فرمان‌ها از مسئله کوئرا گرفته شده‌اند.

۱. موجودیت‌ها و محدودیت‌ها

موجودیتمشخصات
دانشجو Studentنام name، کد ملی identical_num، سال ورودی entering_year، رشته field و فهرست کلاس‌ها
استاد Professorنام، کد ملی، رشته، فهرست کلاس‌های تدریس
کلاس Courseنام، شناسه class_id، رشته، استاد، فهرست مرتب دانشجویان، نمره‌های نهایی

نام و رشته: رشته‌ای با ۱ تا ۲۰ حرف کوچک انگلیسی؛ کد ملی و شناسه کلاس: دقیقاً ۱۰ رقم (به صورت رشته برای حفظ صفرهای ابتدا)؛ سال ورودی: عدد صحیح ۱۳۰۰ تا ۱۵۰۰. شناسه ملی دانشجو و استاد در یک فضای یکتا قرار دارد. ثبت‌نام دانشجویان و استادها و ترتیب کلاس‌ها باید حفظ شود.

۲. طراحی شی‌گرا

حداقل چهار کلاس Student، Professor، Course و Golestan داشته باشید. هر شیء وظایف مربوط به خودش را نگهداری کند. ویژگی‌های اصلی از طریق @property فقط‌خواندنی در دسترس باشند و تغییر وضعیت تنها از طریق متدهای مجاز انجام شود. برای نگهداری داده‌ها می‌توانید از فهرست و دیکشنری استفاده کنید؛ استفاده از Class Attribute، ارث‌بری یا Metaclass الزامی نیست.

برای تست‌پذیری، متدهای سامانه نتیجه فرمان را به شکل رشته برگردانند؛ در فایل main.py فقط این رشته‌ها چاپ شوند. تغییر نام فرمان‌ها و پیام‌های خروجی مجاز نیست.

۳. پیاده‌سازی مرحله‌ای پروژه

پیاده‌سازی را در سه فاز انجام دهید. نام کلاس مدیریت Golestan و سازنده آن Golestan() است. متدهای هر فاز پس از تکمیل همان فاز قابل آزمایش‌اند. نام متدها، ترتیب پارامترها، خروجی‌ها و متن پیام‌های خطا باید دقیقاً مطابق قرارداد باشد تا تست‌های دانشجویان دیگر روی پروژه شما اجرا شوند.

فاز اول

ثبت اولیه اطلاعات

در این فاز، اشیای Student، Professor و Course ساخته و در سامانه نگهداری می‌شوند. هنوز نیازی به ثبت‌نام در کلاس یا نمره‌دهی نیست.

متدهای الزامی این فاز

نام متد در کلاس Golestanپارامترها به ترتیبرفتار و نتیجه
register_studentname, identical_num, entering_year, fieldwelcome to golestan / this identical number previously registered

قواعد و نکات این فاز

  • نام و رشته باید شامل ۱ تا ۲۰ حرف کوچک انگلیسی باشند. کد ملی و شناسه کلاس رشته ۱۰ رقمی‌اند و صفر ابتدایی آن‌ها باید حفظ شود.
  • سال ورودی باید عدد صحیح بین ۱۳۰۰ تا ۱۵۰۰ باشد.
  • شناسه ملی دانشجو و استاد در یک فضای مشترک یکتا است. ثبت تکراری مجاز نیست.
  • برای ثبت موفق دانشجو یا استاد پیام welcome to golestan و برای ثبت کلاس پیام class added successfully برگردانده شود.
پیشنهاد تست برای پایان فاز: ثبت موفق و تکراری دانشجو، استاد و کلاس؛ اعتبار شناسه‌ها و حفظ ترتیب ثبت.
فاز دوم

مدیریت ثبت‌نام و کلاس‌ها

با تکیه بر موجودیت‌های فاز اول، دانشجو به کلاس اضافه و استاد به کلاس تخصیص داده می‌شود. متدهای وضعیت نیز فهرست ثبت‌نام‌ها و کلاس‌ها را ارائه می‌کنند.

متدهای الزامی این فاز

نام متد در کلاس Golestanپارامترها به ترتیبرفتار و نتیجه
add_studentidentical_num, class_idinvalid student → invalid class → student field is not match → student is already registered → success
add_professoridentical_num, class_idinvalid professor → invalid class → professor field is not match → this class has a professor → success
student_statusidentical_numStudent name, entry year, field, enrolled course names; no output if none
professor_statusidentical_numProfessor name, field, taught course names; no output if none
class_statusclass_idProfessor name (or None) followed by student names

قواعد و نکات این فاز

  • رشته دانشجو یا استاد باید با رشته کلاس یکسان باشد. ثبت دوباره دانشجو در یک کلاس و تعیین استاد دوم مجاز نیست.
  • برای add_student ترتیب بررسی خطاها: invalid student، invalid class، student field is not match، student is already registered. در موفقیت: student added successfully to the class.
  • برای add_professor ترتیب خطاها: invalid professor، invalid class، professor field is not match، this class has a professor. در موفقیت: professor added successfully to the class.
  • گزارش‌ها ترتیب ثبت‌نام و تخصیص را حفظ می‌کنند؛ در class_status اگر استاد وجود ندارد، مقدار None نشان داده می‌شود.
پیشنهاد تست برای پایان فاز: عدم انطباق رشته، ثبت‌نام تکراری، اولویت خطا و ترتیب اسامی در گزارش‌ها.

ثبت نمرات و گزارش‌های تحصیلی

پس از ثبت‌نام و تخصیص استاد، امکان ثبت یا اصلاح نمره نهایی و دریافت گزارش نمرات، میانگین و رتبه‌بندی فراهم می‌شود.

متدهای الزامی این فاز

قواعد و نکات این فاز

  • فقط استاد همان کلاس برای دانشجوی ثبت‌نام‌شده می‌تواند نمره نهایی ثبت کند. نمره عدد صحیح بین ۰ و ۲۰ است؛ نمره جدید جایگزین قبلی می‌شود.
  • اولویت خطاهای set_final_mark به ترتیب: invalid professor، invalid student، invalid class، professor class is not match، student did not registered. در موفقیت: student final mark added or changed.
  • در mark_student ابتدا دانشجو، کلاس و ثبت‌نام بررسی می‌شوند؛ در mark_list ابتدا کلاس، وجود استاد و وجود دانشجو بررسی می‌شود.
  • میانگین فقط بر اساس آخرین نمرات ثبت‌شده و با دقیقاً دو رقم اعشار محاسبه می‌شود. در نبود نمره، None برگردانده شود.
  • در top_student تساوی میانگین به نفع دانشجوی زودتر ثبت‌شده است. در نسخه آموزشی، دانشجوی بدون نمره در رتبه‌بندی شرکت نمی‌کند؛ این یک قرارداد تکمیلی برای رفع ابهام منبع است.
پیشنهاد تست برای پایان فاز: اصلاح نمره، محاسبه میانگین، خروجی None، اولویت خطا و تعیین دانشجوی برتر.

۵. تست‌نویسی و ارزیابی متقابل

حداقل ۱۵ تست با کتابخانه unittest بنویسید که هر سه فاز را پوشش دهند: شناسه تکراری، اختلاف رشته، ثبت‌نام تکراری، ترتیب خطا، جایگزینی نمره، میانگین، دانشجوی برتر و وضعیت‌های بدون داده. تست‌ها باید قابل اجرای مستقل باشند. در Peer Testing تست‌های خود را روی پروژه دو همکلاسی که مدرس تعیین می‌کند اجرا کنید و نتایج را گزارش دهید.

۶. قابلیت خلاقانه

هر دانشجو یک قابلیت جدید به سامانه اضافه کند؛ برای مثال حذف درس (با قواعد مشخص)، کارنامه کامل، تشخیص مشروطی یا رتبه‌بندی پیشرفته. قابلیت باید مستند شود و دست‌کم سه تست مستقل داشته باشد. قابلیت جدید نباید رفتار استاندارد فرمان‌های مسئله را تغییر دهد.

۷. دفاع شفاهی و استفاده از AI

تحویل GitHub تنها بخشی از ارزیابی است. هر دانشجو در جلسه شفاهی باید طراحی اشیا، جریان ثبت‌نام، ثبت نمره و تست‌های خود را توضیح دهد و یک تغییر کوچک یا تست جدید را بدون کمک AI انجام دهد. استفاده از AI هنگام توسعه با اعلام آن در README مجاز است؛ فهم و توانایی تغییر کد الزامی است.
